### 1. Open the existing property before creating another

1. Sign in to Search Console with the authorized company account.
2. Check the property selector for either:
   - Domain property: `jinghangsc.com`; or
   - existing URL-prefix property: `https://jinghangsc.com/`.
3. Prefer the existing verified property if it is under the correct owner. Do not create duplicates without a reporting reason.
4. If access belongs to another authorized owner, request user access instead of replacing their verification token.

### 2. If a Domain property is needed

1. Add `jinghangsc.com` as a Domain property, without `https://`, `www`, or a path.
2. Copy the exact TXT record generated by Search Console.
3. Add that record in the active Cloudflare DNS zone.
4. Do not invent, abbreviate, or reuse a token from another property.
5. Keep the verification record after verification; deleting the active ownership token can remove access.

DNS verification requires an authorized Cloudflare user and may require account confirmation. This document does not contain a verification token.

### 3. Confirm the canonical host

In URL Inspection, check:

- user-declared canonical;
- Google-selected canonical;
- last crawl;
- indexing allowed;
- page fetch;
- referring page and sitemap discovery where shown.

The source declares `https://jinghangsc.com` as canonical. If Google selects another host, investigate redirects, internal links, sitemap URLs, and response headers before changing the canonical strategy.

### 4. Submit the sitemap once

Submit:

`https://jinghangsc.com/sitemap.xml`

Then record:

- submission time;
- processing status;
- discovered URL count;
- any parse or fetch error.

Sitemap acceptance or discovered URLs do not prove indexing, ranking, impressions, clicks, or enquiries. Do not repeatedly resubmit an unchanged sitemap.

### 5. Inspect priority URLs

Use URL Inspection for the canonical form of:

1. `https://jinghangsc.com/`
2. `https://jinghangsc.com/services`
3. `https://jinghangsc.com/china-sourcing`
4. `https://jinghangsc.com/quality-inspection`
5. `https://jinghangsc.com/freight-from-china`
6. `https://jinghangsc.com/ddp-shipping-from-china`
7. `https://jinghangsc.com/hardware-startup-supply-chain-china`
8. the three Insights URLs after any meaningful content update.

Use **Test live URL** when diagnosing a current fetch or markup issue. Use **Request indexing** once after a substantial publish or a verified fix. Repeated requests for an unchanged URL do not accelerate indexing.

Do not use the Google Indexing API for these ordinary company pages.

### 6. Review the reports

- **Page indexing:** distinguish discovered, crawled, indexed, duplicate, redirected, blocked, noindex, soft 404, and server-error states.
- **HTTPS:** confirm Google reports the canonical HTTPS pages correctly.
- **Core Web Vitals:** review mobile and desktop field data when enough traffic exists. “No data” is not a passing score.
- **Performance:** export query, page, country, and device data for the latest 28 days and previous 28 days.
- **Manual actions:** confirm status in the portal.
- **Security issues:** confirm status in the portal.
- **Sitemaps:** check processing status and discovered URLs.

Use this reporting vocabulary:

`discovered → crawled → indexed → impression → click → enquiry`

Never collapse those stages into “ranking” or “customer acquired.”

## Bing Webmaster Tools

Official references:

- [Add and verify a site](https://www.bing.com/webmasters/help/add-and-verify-site-12184f8b)
- [Submit and review sitemaps](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed)
- [URL Inspection](https://www.bing.com/webmasters/help/URL-Inspection-55a30305)
- [Search Performance](https://www.bing.com/webmasters/help/search-performance-c680da36)
- [URL submission and IndexNow](https://www.bing.com/webmasters/help/URL-Submission-62f2860b)
- [IndexNow overview](https://www.bing.com/webmasters/help/indexnow-0z209wby)

### 1. Verify the correct site

1. Sign in with an authorized account.
2. Check whether `https://jinghangsc.com` already exists.
3. If Google Search Console is verified under the same authorized user, consider Bing's official Search Console import.
4. Otherwise use a Bing-provided verification method.
5. The repository contains a verification meta tag, but do not assume it matches the current Bing account. Compare it with the portal before changing or removing it.

If the portal again reports a fetch or unexpected error:

- confirm the homepage is publicly reachable;
- inspect the rendered `<head>` and response status;
- verify the exact token;
- check that security headers do not block Bing's fetch;
- retry after the platform error clears;
- record the error text and time without exposing credentials.

### 2. Submit the sitemap

Submit:

`https://jinghangsc.com/sitemap.xml`

Record the submitted/discovered date, last processed date, status, and discovered URL count. A successful sitemap status is a discovery signal, not proof of indexing or search performance.

### 3. Inspect priority URLs

Use Bing URL Inspection for the homepage, service hub, five specialist pages, and any materially changed Insight. Review:

- index status;
- crawl status and last crawl;
- robots access;
- canonical;
- detected structured markup;
- live URL result.

Request recrawl only when the URL is new or materially changed.

### 4. Use IndexNow only for real changes

The repository contains an IndexNow key file. Before any submission:

1. confirm the deployed key file is reachable at the root and belongs to this site;
2. keep the key out of logs beyond what the public protocol requires;
3. submit only URLs that were added, materially updated, or deleted;
4. log URL, UTC time, Beijing time, content hash, HTTP result, and failure reason;
5. do not submit the unchanged sitemap or every URL every day.

IndexNow notifies participating engines that a URL changed. It does not guarantee crawl, indexing, ranking, clicks, or enquiries.

### 5. Review Bing reports

- Search Performance: queries, pages, impressions, clicks, CTR, country, and device where available.
- URL Inspection: canonical, crawl, index, and markup findings.
- Sitemaps: processing and discovered URL status.
- Crawl information: errors, blocked resources, redirects, and server failures.
- IndexNow: actual submission history and response status.
